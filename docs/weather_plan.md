# WinIsle 天气模块 · 技术选型与功能分析

> 状态：2026-11-18 分析稿（未实现，供拍板）。当前 `src/main.rs` 里 `Module::Weather` 仍是
> `draw_placeholder_page(..., "天气", "天气模块即将上线")` 占位页；折叠态也还没有天气数据。

## 0. 一句话结论

- **没有可直接套用的“天气框架”**。真正能复用的是两块：**天气数据 API** + **天气图标/动画资源**。
- 推荐基线：**Open-Meteo（免 key、开源、全球+中国 CMA 模型）+ Meteocons（MIT、475 个动画天气图标）**，
  用 Rust 现有 `ureq + serde_json` 拉数据，图标在 egui 里用**程序化绘制 或 烘焙帧图集**播放动画。
- 图标：**所有主流数据源都返回机器可读的 weather code，图标完全可控**；关键是做一张
  `code → 图标状态（区分昼夜/强度）` 的映射表，并留 `unknown` 兜底。
- 最符合本项目“纯原生 / 轻量 / 单 exe / 无 WebView”的动画落地方式：**egui painter 程序化动画** 为主，
  需要高保真时再把 Meteocons 烘焙成帧序列（`.rgba` 图集，沿用现有 `include_bytes! + load_texture` 管线）。
- **用户端零 key（定稿原则）**：用户打开即用，不出现注册 / Key / 数据源这些概念（见 §9.3）。

## 1. 现状盘点

- 技术栈：Rust + egui/eframe 0.31（glow/OpenGL），无 Electron/WebView，单 exe。
- 网络：已有 `ureq`（TLS/native-certs/json/gzip）+ `serde_json`，`src/update.rs`、`src/lyrics.rs` 已在用。
- 图/贴图：`image` crate；贴图走 `egui::ColorImage::from_rgba_unmultiplied` + `ctx.load_texture`，
  素材用 `include_bytes!("assets/*.rgba")` 编译进 exe（`src/main.rs:3403` 及 `make_tex` `src/main.rs:4435`）。
- 线程模型：`std::thread::spawn` + `std::sync::mpsc`（`src/main.rs:849-852`、`2683-2705`），后台拉数据、UI 轮询 `try_recv`。
- 已有导航：左侧「音乐 / 天气」两项（`src/main.rs:2508`），`Module::Weather` 分支直接换成真实页面即可。
- 折叠态天气（README 说的“折叠态常显天气”）**尚未实现**，需要一起做。

结论：**基础设施齐全，天气模块 = 纯新增 `src/weather.rs` + 替换占位页，不需要引入重型依赖。**

- 两家可商用、可改。**Meteocons 是唯一“自带高质量动画”的**（475 个、四风格、MIT），这是动态图标的首选素材。

## 3. 需要实现的功能（功能清单）

### 3.1 定位 / 城市
- 城市搜索（Open-Meteo Geocoding API 或和风 GeoAPI）：输入城市名 → 选 lat/lon。
- 多城市保存 + 设置默认城市；左右切换城市。
- IP 自动定位兜底（首次启动没设城市时）；支持“手动指定优先”。
- 记住上次城市。

### 3.2 数据获取与缓存
- **实时**：温度、体感、天气现象(code+text)、湿度、风向风速、气压、能见度、露点、紫外线。
- **逐小时**：未来 24h 温度曲线、天气、降水概率、风速。
- **多日**：7（Open-Meteo 可到 16）天，最高/最低、天气、降水概率、日出日落。
- **空气质量**：AQI + PM2.5/PM10/O3/NO2（Open-Meteo Air Quality API）。
- **预警**（仅和风/彩云）：暴雨/高温/大风等。
- **生活指数**（仅和风，可选）：穿衣、紫外线、洗车、运动。
- 单位切换：℃/℉、km/h / m/s / 风力等级、hPa/mmHg。
- 中文天气文案映射（WMO code 或和风 text）。
- **缓存**：`data/cache/weather.json`，按 TTL（实时 5–10min、预报 30–60min）；失败/断网用缓存 + 显示“更新于 xx:xx”。
- **异步**：后台线程拉取，UI 不卡；超时/重试；切到天气页或每 10min 自动刷新。

### 3.3 展示（展开页）
- 顶部：城市名 + 当前大号温度 + 天气现象 + 体感 + 今日高低温 + **主图标（带动画）**。
- 逐小时横条：温度折线 + 小时图标 + 降水概率。
- 多日纵向列表：星期/日期、图标、最高最低**温度区间条**。
- 详情网格：湿度/风/气压/能见度/紫外线/日出日落/AQI。
- 数据来源与更新时间标注（Open-Meteo 需 CC BY 署名）。
- **折叠态（胶囊）**：常显当前温度 + 小图标，展开看详情（与 README 描述一致）。

### 3.4 系统 / 体验
- 背景随天气与昼夜变化（晴=暖光、雨=冷蓝、夜=深色），弱化、不抢唱机视觉。
- 动画降帧（约 20–30fps 或仅在展开可见时播放），避免 16ms 全量重绘下 CPU 飙升。
- 加载中/失败/空状态占位（骨架 + 重试按钮）。

## 4. 图标与动态动画怎么做（核心难点）

egui 是即时模式原生渲染，**不能直接播放 animated SVG / Lottie**（`egui_extras` 的 SVG 只静态光栅化，SMIL/CSS/Lottie 动画都不动）。三条落地路线：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 程序化绘制（推荐主用）** | 用 `painter` 画日/云/雨/雪/雷/雾/月，按时间改旋转/位移/透明度 | 二进制几乎不增、与岛视觉统一、任意配色/尺寸、无额外依赖 | 每个状态手写，质感上限取决于投入 |
| **B. 烘焙帧图集** | 离线用 Node(resvg+puppeteer/lottie) 把 Meteocons 动画导出为 PNG 帧 → 合成 `.rgba` 图集 → 运行时 `load_texture` 翻帧播放 | **Meteocons 级高保真动画**、运行时简单 | 素材体积增加（可控：限 12–16 状态×~24 帧×64px）；需一次性烘焙脚本 |
| **C. Lottie 运行时** | 引入 rlottie/lottie-rs 播放 Lottie | 直接吃 Lottie | 需 C++/额外重依赖，违背“轻量原生” |

**推荐：A 为主 + B 兜底高保真**。先做一套约 12–16 个核心状态的程序化动画（晴昼/晴夜/多云/阴/小雨/中大雨/雷阵雨/雪/雨夹雪/雾/霾/大风），
若用户觉得质感不够，再用 B 把 Meteocons 烘焙进来替换。

### 图标映射表（必须做，且留 unknown 兜底）
`weather code → (状态, 昼夜)`，例：
- 晴 → clear-day / clear-night（夜：月+星）
- 少云/多云/阴 → partly-cloudy / cloudy / overcast
- 阵雨/雷阵雨/各种雨强度 → rain 分级
- 雪/雨夹雪/冻雨 → snow / sleet
- 雾/霾/沙尘 → fog / haze / dust
- 未知 → unknown（和风明确警告天气代码会增删改，**必须容错**）

## 5. 架构与改动点（Rust / egui）

- 新增 `src/weather.rs`：
  - 数据结构：`WeatherData { current, hourly[], daily[], aqi?, updated_at, tz }`、`Current/Hourly/Daily/Aqi`。
  - `trait Provider { fn fetch(lat,lon,..) -> Result<WeatherData> }`，实现 `OpenMeteo`、可选 `QWeather`。
  - 缓存读写、WMO/和风 code→文案+图标状态映射、单位换算。
- `src/main.rs`：
  - `Module::Weather` 分支 → `draw_weather_page(...)`（替换 `draw_placeholder_page`）。
  - 新增字段：`weather_rx: Option<mpsc::Receiver<...>>`、缓存的 `WeatherData`、贴图/动画时钟。
  - 折叠态胶囊加温度+小图标。
  - 设置页只加“天气：城市 / 单位”（**不出现数据源 / Key**）。
- 依赖：**默认零新增**（`ureq + serde_json + image` 已有）。仅当走方案 B 时才在**构建期**用 Node 脚本烘焙，运行时不加依赖。
- 缓存：`data/cache/weather.json`（沿用 `paths::file()` 到 exe 同目录 `data`）。
- 刷新：进入天气页 + 每 ~10min 后台刷新；失败保留旧数据。

## 6. 风险 / 坑
1. Open-Meteo 免费仅**非个人商用**；本项目 MIT 开源、个人桌面用 OK，若上架商用需订阅并 CC BY 署名。
2. 国内直连 `open-meteo.com` 可能慢/不稳 → Provider 可切换 + 缓存兜底 + 超时快速失败。
3. 天气代码会变 → 映射表容错，未知一律 unknown。
4. 动画 CPU：本项目逐帧重绘，图标动画要限帧/仅在展开可见时跑。
5. 时区：预报按**地点时区**，不要用本机时区硬算日出日落。
6. 图标版权署名：MIT 也要在 `THIRD_PARTY_NOTICES.md` 补 Meteocons / QWeather Icons。

### 9.3 分发场景的 key 问题（重要）

开源桌面应用**不能把 key 打进 exe**（会被扒出来滥用配额）。三种解法：
1. **用无 key 第三方接口**（默认零配置，如 itboy）—— 体验最好，但依赖第三方稳定性；
2. **让用户自己填 key**（高德/和风）—— 最正规、最稳，但要多一步设置；
3. 自建代理转发 key —— 对个人项目过重。

**定稿原则（用户端零 key）**：对用户就是「打开即用」——不注册、不填 key、不暴露数据源概念。实现上：
- 默认 **itboy**（无 key、国内直连、中文、15 天、AQI 全）；
- 代码里**多个无 key 源互为兜底**：itboy（主）→ 中国天气网实时（备）→ Open-Meteo（海外兜底），主源失败自动切下一个，用户无感；
- **强缓存**：断网/失败显示上次数据 + 更新时间。
- 更高稳定性/预警属于**开发者后台自己解决**（自建代理或服务端内置 key 转发），**绝不把 key 抛给用户**。高德/和风仅作为“开发者可替换的后端”，不出现在用户设置里。
